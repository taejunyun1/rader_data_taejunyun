# Research Radar UI 재설계 사양

- 작성일: 2026-08-21
- 대상: `web/` React SPA 전체 화면
- 상태: 사용자 승인 디자인
- 근거 문서: `docs/spec-v0.1.txt`, `docs/SPEC.md`, `docs/DEV_PLAN.md`, `docs/PROJECT_CONTEXT.md`

## 1. 목적

Research Radar를 기능 중심의 초기 UI에서 읽기 중심의 개인 연구 편집 도구로 재설계한다. 서버 API, 데이터 모델, 수집·분석 파이프라인은 유지하고 프론트엔드 정보 구조와 표현 계층을 정비한다.

핵심 사용 흐름은 다음과 같다.

```text
레이더에서 현재 흐름과 읽을 자료 확인
→ 발견 또는 저장소에서 자료 선택
→ 원문·출처·시스템 해석을 구분해 읽기
→ 발전/보관/관찰/제외 판단
→ 선택한 질문과 자료를 착즙
→ 결과를 읽고 일부만 다시 착즙
```

성공 기준은 기능 수가 아니라 다음 세 가지다.

1. 사용자가 로그인 후 무엇을 읽어야 하는지 바로 알 수 있다.
2. 원자료와 AI 해석을 혼동하지 않고 충분히 읽을 수 있다.
3. 읽은 뒤 분류하고 다음 연구 행동으로 넘어가는 비용이 낮다.

## 2. 확정된 디자인 방향

### 2.1 화면별 방향

- 레이더 대시보드: A안인 `연구 편집 데스크`를 사용한다.
- 개별 기능 페이지: B안의 질문·읽기 중심 구조와 C안의 고밀도 인덱스를 결합한다.
- 발견과 저장소: 같은 `목록 → 읽기 → 판단` 작업 공간을 공유한다.
- 착즙: 카드 대시보드가 아니라 긴 연구 문서처럼 읽는 구조를 사용한다.
- 받은 자료, 설정, 사용량: 동일한 디자인 시스템을 사용하되 보조 작업 화면으로 절제한다.

### 2.2 시각 원칙

- 배경은 흰색과 중립 회색만 사용한다. 넓은 컬러 배경을 사용하지 않는다.
- 색은 현재 위치, 핵심 CTA, 접근 상태, 관심 변화에만 사용한다.
- 카드 남용을 피하고 구획선, 정렬, 타이포그래피로 구조를 만든다.
- 한 화면에서 가장 강한 CTA는 하나만 둔다.
- 정보 밀도는 높게 유지하되 본문 읽기 폭은 제한한다.
- 장식 애니메이션은 사용하지 않는다. 로딩·상태 전이에 필요한 움직임만 허용한다.

### 2.3 고유 시각 요소

Research Radar의 시그니처는 `관심 스펙트럼 선`이다. 보라색에서 청록·주황·분홍으로 이어지는 3~4px 선을 레이더 요약, 섹션 전환 또는 읽기 판단 영역에 한 번만 사용한다.

이 선은 장식용 그라데이션 배경이 아니라 서로 다른 연구 축의 이동과 연결을 나타낸다. 한 화면에 반복해서 사용하지 않는다.

## 3. 언어와 명칭

전체 인터페이스는 한글을 기본으로 한다. 이는 `docs/SPEC.md` D9의 영문 UI 결정보다 이후 사용자가 확정한 요구를 우선하는 변경이다. 구현 전후 문서에서 이 변경을 명시한다.

주 내비게이션은 다음 명칭을 사용한다.

| 기존 | 표시 명칭 | 설명 |
|---|---|---|
| RADAR | 레이더 | 현재 연구 흐름과 읽을 자료 |
| DISCOVER | 발견 | 외부 후보 검토 |
| RESERVOIR | 저장소 | 보존된 연구 자료 |
| DISTILL | 착즙 | 선택한 맥락의 종합·비평·반대 관점 |
| INBOX | 받은 자료 | 입력과 처리 상태 |
| USAGE | AI 사용량 | 월 예산과 호출 내역 |
| SETTINGS | 설정 | 5개 연구 파라미터와 데이터 관리 |

`Distill`, `Critic`, `Counter`, `Reservoir` 같은 제품 고유 개념은 첫 노출에서만 한글 설명과 영문을 병기할 수 있다. 작가명, 논문명, 저널명과 원문 고유명사는 번역하지 않는다.

버튼은 시스템 용어가 아니라 결과를 설명한다. 예를 들어 `Run`, `Submit`, `Keep` 대신 `이번 주 흐름 종합하기`, `원문에서 읽기`, `보관하기`를 사용한다.

## 4. 디자인 토큰

### 4.1 색상

| 토큰 | 값 | 용도 |
|---|---|---|
| `--color-ink` | `#17181C` | 기본 본문·강조 텍스트 |
| `--color-surface` | `#FFFFFF` | 기본 표면 |
| `--color-soft` | `#F7F8FA` | 목록·보조 표면 |
| `--color-line` | `#E4E6EB` | 구획선·입력 테두리 |
| `--color-accent` | `#6547FF` | 현재 위치·주 CTA·선택 상태 |
| `--color-positive` | `#008D86` | 읽기 가능·완료·검증됨 |

경고와 접근 제한에는 주황 계열 `#D85A22`, 오류에는 적색 계열을 의미 토큰으로만 추가한다. 상태는 색상뿐 아니라 텍스트와 아이콘으로 함께 표현한다.

관심 스펙트럼은 `#6547FF → #00A6FF → #00B894 → #FFAD00 → #E64070` 순서로 사용한다.

### 4.2 타이포그래피

- 제목·본문: `Pretendard Variable`, `Apple SD Gothic Neo`, `Noto Sans KR`, `system-ui`, sans-serif 순서
- 데이터·날짜·비용: `ui-monospace`, `SFMono-Regular`, monospace
- 외부 폰트 CDN은 사용하지 않는다.
- 본문 읽기 크기: 데스크톱 15~16px, 줄간격 1.7~1.8
- 본문 최대 폭: 680~760px
- 화면 제목: 28~32px, 굵기 700~760
- 메타데이터: 11~12px, 대비는 WCAG AA를 만족하도록 조정

### 4.3 간격과 형태

- 기본 간격 단위: 4px
- 주요 간격: 8, 12, 16, 24, 32, 48px
- 입력·버튼 모서리: 6~8px
- 큰 작업 영역 외곽 모서리: 최대 12px
- 캡슐 형태는 필터와 짧은 상태에만 사용한다.
- 그림자는 앱 전체가 아닌 떠 있는 팝오버·모달에만 사용한다.

## 5. 전역 정보 구조

### 5.1 App Shell

데스크톱 기본 구조는 고정 왼쪽 사이드바와 콘텐츠 영역이다.

```text
┌──────────────┬──────────────────────────────────────────────┐
│ Research     │ 페이지 제목                   페이지 주 CTA │
│ Radar        ├──────────────────────────────────────────────┤
│              │                                              │
│ 레이더       │ 페이지별 작업 공간                           │
│ 발견         │                                              │
│ 저장소       │                                              │
│ 착즙         │                                              │
│ 받은 자료    │                                              │
│              │                                              │
│ AI 사용량    │                                              │
│ 설정         │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

- 사이드바에는 핵심 흐름 순서대로 메뉴를 배치한다.
- 발견 후보 수, 받은 자료 실패 수처럼 행동이 필요한 경우만 숫자를 표시한다.
- AI 사용량과 설정은 사이드바 하단 유틸리티로 분리한다.
- 현재 앱 하단의 API/AI 디버그 텍스트는 운영 UI에서 제거한다. 필요한 상태는 설정의 진단 영역이나 개발 환경에서만 노출한다.

### 5.2 공통 페이지 헤더

페이지 제목, 보조 필터, 단일 주 CTA를 한 줄에 배치한다. CTA가 없는 화면은 억지로 만들지 않는다.

예시:

- 레이더: 기간 필터 + `이번 주 흐름 종합하기`
- 발견: 후보 필터 + `새 자료 찾기`
- 착즙: 세션 이력 + `새 착즙 시작`
- 받은 자료: 입력 방식 선택 + `자료 추가`

### 5.3 전역 작업 상태

현재 상단의 작은 작업 텍스트를 `Task Center`로 정리한다.

- 실행 중: 현재 단계와 진행률
- 완료: 결과 화면으로 이동하는 링크
- 실패: 원인 요약과 `다시 시도`
- 최근 작업 최대 3개만 표시
- 일반 성공 메시지는 짧은 토스트로 처리하고 지속 메시지로 남기지 않는다.

## 6. 화면별 설계

### 6.1 레이더

레이더는 로그인 후 기본 화면이다. A안의 연구 편집 데스크를 적용한다.

주 콘텐츠 순서:

1. 기간과 연구 흐름 제목
2. 이번 기간을 설명하는 짧은 종합 문장
3. 상승 관심, 새 연결, 계속 남은 질문의 인덱스
4. 계속 붙잡을 질문
5. 편향 감시와 반대 관점 힌트

오른쪽 고정 열:

1. 지금 직접 읽을 자료 3개
2. 무료 원문, 기관 인증, 초록만 보기 등 접근 경로
3. 발견 후보 검토, 실패 재시도, 선택 항목 착즙 같은 다음 행동

통계는 관계를 설명할 때만 사용하고 장식용 차트는 만들지 않는다. Snapshot은 자동 준비되지만 AI synthesis는 사용자가 CTA를 눌렀을 때만 실행한다.

### 6.2 발견

발견은 `후보 인덱스 + 읽기 화면 + 판단 레일`의 3열 구조를 사용한다.

왼쪽 후보 인덱스:

- 제목, 출처, 연도, 접근 가능 상태
- 전체, 원문 가능, 학술, 미술, 상태 필터
- 높은 정보 밀도와 키보드 이동
- 선택 항목은 색상 면이 아니라 왼쪽 accent 선으로 표시

가운데 읽기 화면:

- 제목, 저자, 연도, 출처
- 실제 원문으로 이동하는 주 CTA
- `무료 원문`, `기관 인증`, `초록만 보기` 접근 상태
- 발견 경로와 provenance
- 시스템 해석과 원문 발췌의 명시적 구분
- 읽으며 붙잡을 질문

오른쪽 판단 레일:

- `발전시키기`, `보관하기`, `관찰하기`, `제외하기`
- 관련 저장소 자료와 현재 연구 질문
- 읽기 메모

e-flux, RISS, OpenAlex, arXiv 등은 출처명과 실제 읽기 링크를 제공한다. 접근 경로가 확인되지 않은 경우 가능한 것처럼 표시하지 않는다.

### 6.3 저장소

저장소는 발견과 같은 읽기 작업 공간을 재사용한다. 차이는 다음과 같다.

- 왼쪽 인덱스는 자료 유형, 신뢰도, 토픽, 상태, 검색 결과를 제공한다.
- 가운데는 저장된 원본 버전, 시스템 분석, 질문, fragments를 읽기 순서로 재구성한다.
- 원본과 AI 해석을 탭으로 숨기기보다 한 화면에서 출처 레이블로 구분한다.
- 오른쪽 판단 레일은 기존 신호 상태, 재분석, 버전 보기, 읽기 메모를 제공한다.
- 재분석은 주 CTA가 아니라 보조 위험 작업으로 둔다.

검색 결과에서 자료를 열어도 동일한 읽기 작업 공간으로 진입한다. 목록 상태와 스크롤 위치는 상세 화면을 닫은 뒤 유지한다.

### 6.4 착즙

착즙 결과는 긴 연구 문서 형태로 표시한다.

왼쪽 문서 목차:

- 핵심 흐름
- 지금 읽을 자료
- 남은 질문
- 연구 간극
- 연구 방향
- 작업 방향
- 비평과 반대 관점

가운데 읽기 문서:

1. 종합 제목과 짧은 서문
2. 사용한 원자료 수와 provenance
3. 핵심 흐름과 키워드
4. 실제 접근 경로가 확인된 읽을 자료
5. 남은 질문과 연구 간극
6. 연구·작업 방향
7. Critic과 Counter

오른쪽 선택 레일:

- 문장, 질문, 자료, 연구 간극의 선택 목록
- 선택 수와 예상 실행 상태
- `선택 항목 다시 착즙` 주 CTA
- `이번 결과 보관` 보조 CTA

Reading Queue를 키워드나 방향보다 앞에 배치한다. Critic과 Counter는 결과를 가로막는 경고 모달이 아니라 문서 끝에서 함께 읽는 검증 레이어로 표현한다.

### 6.5 받은 자료

받은 자료는 입력과 처리 상태를 한 화면에 섞지 않는다.

- 상단 `자료 추가` CTA에서 텍스트, URL, 파일을 선택한다.
- 데스크톱에서는 드래그 앤 드롭을 지원한다.
- 기본 본문은 최근 처리 목록이다.
- 각 행에는 자료명, 입력 유형, 현재 단계, 시간만 표시한다.
- 실패한 행에만 오류 요약과 `다시 시도`를 표시한다.
- 상세 처리 단계는 행 확장 또는 상세 패널에서 확인한다.
- 성공한 자료는 `저장소에서 읽기`로 연결한다.

### 6.6 설정

설정은 사용자가 관리해야 하는 것만 보여준다.

1. 연구 성향: 5개 상위 파라미터와 프리셋
2. 홈페이지: 동기화 상태와 수동 동기화
3. 데이터: JSON, Markdown, CSV, 원본 백업
4. 유지보수: 임베딩·토픽 재처리 같은 비일상 작업

유지보수 작업은 접힌 `고급 관리` 영역에 둔다. 5개 파라미터는 한글 설명과 양 끝 의미를 함께 표시하고 수치 자체를 강조하지 않는다.

### 6.7 AI 사용량

사용량은 분석 대시보드가 아니라 예산 안전장치다.

- 이번 달 사용액, 예산, 남은 금액
- 80% 경고와 100% 차단 상태
- 목적별·모델별 사용 내역
- 일별·월별 추이는 작은 표 또는 절제된 막대로 제공
- 비용이 0에 가까워도 지나치게 큰 숫자 카드로 과장하지 않는다.

## 7. 공통 컴포넌트 경계

다음 단위로 분리한다.

| 컴포넌트 | 책임 | 주요 사용처 |
|---|---|---|
| `AppShell` | 사이드바, 페이지 헤더, 콘텐츠 프레임 | 전체 |
| `SidebarNav` | 한글 메뉴, 현재 위치, 행동 수 | 전체 |
| `PageHeader` | 제목, 필터, 단일 주 CTA | 전체 |
| `TaskCenter` | 장기 작업 진행·완료·실패 | 전체 |
| `SplitWorkspace` | 인덱스·읽기·판단 3열 레이아웃 | 발견, 저장소 |
| `SourceIndex` | 자료 목록, 필터, 키보드 선택 | 발견, 저장소 |
| `ReadingPane` | 제목, 출처, 해석, 발췌, 질문 | 발견, 저장소 |
| `SourceAccessBadge` | 무료/인증/초록/PDF 접근 상태 | 레이더, 발견, 착즙 |
| `ProvenanceNotice` | SOURCE/INTERPRETATION/SYNTHESIS 구분 | 발견, 저장소, 착즙 |
| `DecisionRail` | 발전/보관/관찰/제외와 메모 | 발견, 저장소 |
| `DocumentOutline` | 긴 결과의 섹션 이동 | 착즙 |
| `SelectionTray` | Re-Distill 선택 목록 | 착즙 |
| `StatusMessage` | 빈 상태·경고·오류·복구 행동 | 전체 |

화면별 API 호출과 도메인 상태는 각 view에 남기되 시각 컴포넌트는 API를 직접 호출하지 않는다. 이 경계로 디자인 변경이 데이터 로직을 흔들지 않게 한다.

## 8. 데이터 흐름과 상태

### 8.1 자료 읽기

```text
필터 또는 검색
→ 목록 API
→ source/candidate 선택
→ 상세 API
→ ReadingPane 렌더링
→ 사용자 신호 기록
→ 목록 상태·DecisionRail 갱신
```

- 상세 데이터를 불러오는 동안 목록은 유지한다.
- 새 항목을 선택하면 기존 읽기 위치를 버리고 상세 상단으로 이동한다.
- 분류 action은 낙관적으로 표시하되 실패하면 이전 상태로 복원한다.
- 외부 원문 링크는 새 탭으로 열며 출처와 접근 상태를 함께 기록한다.

### 8.2 착즙

```text
세션 실행
→ Task Center 진행 표시
→ 세션 상세 수신
→ 읽기 문서 렌더링
→ 요소 선택
→ SelectionTray
→ Re-Distill
→ 새 세션 연결 및 문서 교체
```

장기 작업은 화면을 막는 전체 로딩으로 처리하지 않는다. 사용자는 다른 페이지로 이동할 수 있고 완료 시 해당 결과로 돌아올 수 있어야 한다.

## 9. 오류·빈 상태·접근 상태

- 네트워크 오류: 무엇을 불러오지 못했는지와 `다시 시도`를 제공한다.
- 처리 실패: 원본 보존 여부와 재처리 가능 여부를 명시한다.
- 빈 발견 후보: 다음 자동 실행 시점과 `새 자료 찾기`를 제시한다.
- 빈 저장소: 텍스트, URL, 파일 중 가장 빠른 첫 입력을 제안한다.
- 빈 착즙: 필요한 최소 자료 상태와 `새 착즙 시작`을 제시한다.
- 원문 접근 불명: `원문 가능`으로 표시하지 않고 `출처에서 확인`으로 표현한다.
- 예산 차단: 사용량과 차단 이유를 보여주고 저장소·검색·읽기는 계속 사용할 수 있음을 설명한다.

오류 문구는 사과나 모호한 실패 메시지 대신 원인과 복구 행동을 말한다.

## 10. 반응형과 접근성

제품은 데스크톱 우선이지만 다음 최소 기준을 충족한다.

- 1280px 이상: 3열 읽기 작업 공간
- 900~1279px: 판단 레일을 접을 수 있는 패널로 전환
- 899px 이하: 사이드바 축소, 목록과 읽기를 순차 화면으로 전환
- 640px 이하: 핵심 CTA를 하단 고정 영역으로 전환 가능
- 모든 기능은 키보드로 접근 가능
- 포커스 링은 accent 색으로 명확히 표시
- 본문·메타데이터 대비는 WCAG AA 기준 충족
- 상태를 색상만으로 전달하지 않음
- `prefers-reduced-motion`에서 진행 애니메이션 최소화

## 11. 구현 제약

- Worker API와 D1/R2 스키마를 UI 작업 때문에 변경하지 않는다.
- 새 전역 상태 라이브러리를 도입하지 않는다.
- 스타일은 현재 인라인 객체에서 CSS 토큰과 재사용 클래스/컴포넌트로 이동한다.
- 외부 UI 프레임워크와 폰트 CDN을 추가하지 않는다.
- 기존 기능과 API 경로를 유지하며 화면 구조만 교체한다.
- 모델명, 비용 정책, provenance 정책은 기존 문서를 따른다.
- V0 비목표인 챗봇, 관리자 패널, 지식 그래프 UI를 추가하지 않는다.

## 12. 검증 기준

### 공통

- 모든 주 화면과 상태 문구가 한글로 표시된다.
- 현재 페이지와 주 CTA가 즉시 구분된다.
- 본문 폭과 줄간격이 긴 읽기에 적합하다.
- 모바일과 좁은 데스크톱에서 가로 스크롤 없이 핵심 기능을 사용할 수 있다.
- 키보드 포커스와 오류 복구 행동이 보인다.

### 읽기·provenance

- 발견, 저장소, 착즙에서 원자료와 시스템 해석이 시각적으로 구분된다.
- 읽을 자료마다 실제 링크와 접근 상태가 표시된다.
- RISS는 무료 원문, 기관 인증, 초록만 보기 상태를 가능한 범위에서 구분한다.
- 링크가 없는 후보를 읽을 수 있는 자료처럼 표시하지 않는다.

### 핵심 흐름

- 레이더에서 읽을 자료로 한 번의 행동으로 이동할 수 있다.
- 자료를 읽은 뒤 같은 화면에서 발전/보관/관찰/제외할 수 있다.
- 착즙 결과에서 요소 선택과 Re-Distill을 화면 이탈 없이 수행할 수 있다.
- 장기 작업 중 다른 화면을 사용할 수 있고 완료 결과로 돌아갈 수 있다.

### 회귀

- Inbox 입력, Reservoir 검색·신호, Discovery action, Distill/Re-Distill, Radar synthesis, Settings 저장, Export, Usage 조회가 기존 API와 동일하게 동작한다.
- `pnpm typecheck`, `pnpm build`를 통과한다.
- 주요 흐름을 브라우저 자동화로 검증한다.

## 13. 범위 제외

이번 UI 재설계에서 다음은 하지 않는다.

- 백엔드 API 재설계
- 데이터베이스 migration
- 새로운 수집 provider 추가
- 전문 PDF 뷰어 또는 웹 원문 프록시
- 사용자 정의 taxonomy 관리
- 관리자 대시보드
- 실시간 협업 또는 다중 사용자 기능

## 14. 구현 순서 원칙

구현은 디자인 시스템과 공통 shell을 먼저 만든 뒤 핵심 읽기 흐름부터 적용한다.

```text
디자인 토큰·AppShell
→ 공통 읽기 작업 공간
→ 발견·저장소
→ 착즙
→ 레이더
→ 받은 자료
→ 설정·사용량
→ 전체 한글화·상태·접근성·반응형 검증
```

각 단계에서 기존 API 동작을 유지하고 화면 단위로 빌드·브라우저 검증을 수행한다.
