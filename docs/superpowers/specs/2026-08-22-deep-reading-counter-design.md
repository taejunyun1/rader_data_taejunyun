# 저장소 심층 정리와 착즙 반대 관점 설계

작성일: 2026-08-22
상태: 구현 전 확정 설계
범위: 저장소 자료 단건 심층 정리, 착즙의 반대 관점 포함 토글과 품질 강화

## 1. 목표

1. 저장소에서 선택한 자료를 기존 자동 분석보다 더 길게 읽고 다시 구조화한다.
2. 사용자는 모델명을 직접 관리하지 않고 `정밀`과 `최고 정밀` 품질 프리셋을 선택한다.
3. 기존 자동 분석과 심층 정리를 구분해 보존하며, 새 결과가 이전 분석을 덮어쓰지 않는다.
4. 착즙할 때 반대 관점을 기본으로 포함하되 사용자가 실행 전에 끌 수 있다.
5. 반대 관점은 단순한 부정이나 억지 반론이 아니라 현재 착즙의 핵심 명제와 정면으로 충돌하면서도 내부 논리와 실제 근거를 갖춘다.

## 2. 현재 상태와 문제

- 기본 자료 분석은 본문 앞 24,000자만 읽고 2–4문장으로 요약한다.
- 저장소의 `다시 분석하기`는 같은 기본 분석을 반복할 뿐 더 긴 독해나 별도 결과를 만들지 않는다.
- `source_analysis`는 이력 저장이 가능하지만 여러 소비자가 단순히 가장 최신 행을 가져오므로, 심층 분석을 추가하면 기본 분석을 오인할 위험이 있다.
- 착즙 Counter는 서버에서 이미 매번 실행되지만 사용자가 실행 여부를 선택할 수 없고 화면에도 결과가 표시되지 않는다.
- 현재 Counter는 착즙 결과만 보고 한 번 생성한다. 반대의 정도와 논리 정합성을 별도로 검증하지 않는다.

## 3. 확정 UX

### 3.1 저장소 심층 정리

자료를 선택하면 읽기 화면의 `시스템 해석` 영역에 다음 컨트롤을 둔다.

- 품질 드롭다운
  - `정밀` — 긴 본문을 나누어 읽고 핵심 구조를 재정리
  - `최고 정밀` — 가장 높은 품질 프로필로 논거와 연결 관계까지 검토
- 기본 선택: `정밀`
- 주 CTA: `심층 정리하기`
- 보조 설명: 읽을 최대 분량과 예상 처리 시간이 달라질 수 있음을 짧게 표시

실제 모델명은 UI에 노출하지 않는다. 서버에서 `정밀 → MODEL_HIGH`, `최고 정밀 → MODEL_DEEP`으로 해석한다. 모델 교체는 Cloudflare 환경변수 변경만으로 가능해야 한다.

실행 상태는 다음과 같이 보인다.

1. `본문 구간을 읽는 중`
2. `핵심 논거를 합치는 중`
3. `최종 정리를 검수하는 중`
4. 성공 토스트 `심층 정리를 완료했습니다.`

결과는 기존 `시스템 해석` 아래의 별도 `심층 정리` 섹션에 표시한다.

- 전체 내용 요약
- 핵심 주장과 근거
- 글의 구조
- 중요한 원문 문장
- 개념·인물·작업 연결
- 연구에 연결할 지점
- 의문점과 한계

상단 메타에는 품질 프로필, 읽은 글자 수/전체 글자 수, 생성 시각을 표시한다. 과거 심층 정리는 접힌 `이전 정리` 목록에서 다시 열 수 있다.

### 3.2 착즙 반대 관점 토글

착즙 CTA 바로 옆에 토글을 둔다.

- 레이블: `반대 관점 포함`
- 기본값: 켜짐
- 설명: `현재 주장과 미학을 정반대 축에서 검증합니다.`
- 꺼짐: Distill과 Critic만 실행하고 Counter 호출은 생략
- 다시 착즙: 선택한 이전 세션의 값을 기본으로 이어받되 실행 전에 변경 가능

토글이 켜진 세션은 결과 문서와 목차에 `정면 반대 관점`을 반드시 포함한다.

표시 구조:

- 현재 중심 주장
- 정반대 명제
- 두 입장이 양립할 수 없는 지점
- 반대 명제가 더 설득력을 갖는 조건
- 반대 방향으로 실행할 연구·작업 방식
- 검증된 작가·작품·텍스트·방법 근거

세션 메타에는 `반대 관점 포함` 또는 `반대 관점 제외` 상태를 남긴다.

기존 `counterStrength`는 더 이상 `약하게 반대할지`를 결정하지 않는다. 토글이 켜진 경우 명제는 항상 정면으로 반대해야 하며, `counterStrength`는 반대 방향을 실제 연구·작업으로 밀어붙이는 강도와 낯섦의 정도만 조절한다. Critic은 토글과 관계없이 항상 실행한다.

## 4. 심층 정리 처리 원칙

### 4.1 입력 선택

- `active_version_id`의 `normalized_text`를 우선 사용하고 없으면 `extracted_text`를 사용한다.
- 짧은 자료는 한 번에 처리한다.
- 긴 자료는 문단 경계를 유지한 채 여러 구간으로 나눈다.
- 1차 구현 상한은 최대 96,000자다. 기본 분석의 24,000자보다 4배 넓다.
- 잘린 경우 결과 메타에 `전체 N자 중 96,000자 분석`을 명시한다.

### 4.2 다단계 요약

1. 구간별로 주장, 근거, 인용 후보, 개념, 불확실성을 구조화한다.
2. 구간 결과를 선택한 동일 품질 프로필로 통합한다.
3. 최종 결과가 원문에 없는 인용을 만들지 않았는지 검증한다.
4. 인용문은 원문 문자열과 일치하는 항목만 저장한다.

모든 구간을 무제한 처리하지 않는다. 최대 4개 구간, 제한된 병렬 처리로 Worker 요청 시간과 비용을 통제한다.

### 4.3 저장과 provenance

- 기존 기본 분석: `analysis_type = basic`
- 새 심층 정리: `analysis_type = deep`
- `provenance = INTERPRETATION`
- payload 메타: `profile`, `sourceCharCount`, `analyzedCharCount`, `chunkCount`
- 모델, 프롬프트 버전, 비용, 자료 버전, 생성 시각을 `source_analysis`에 기록
- 심층 정리는 키워드·질문·fragment 기본 인덱스를 자동으로 다시 쓰지 않는다. 사용자가 보는 읽기 결과로만 먼저 제공한다.

기존 검색·임베딩·착즙 컨텍스트는 명시적으로 최신 `basic` 분석을 사용한다. 심층 정리를 착즙 근거로 사용하는 기능은 별도 승인 전에는 추가하지 않는다.

## 5. 반대 관점 품질 규칙

### 5.1 생성

Counter 입력에는 다음을 함께 제공한다.

- 착즙 결과
- Critic 경고
- 착즙에 사용된 자료의 요약과 원문 fragment
- 사용자 `counterStrength`

Counter는 먼저 현재 착즙의 지배적 명제를 문장으로 고정하고, 그 명제를 동시에 참으로 둘 수 없는 정반대 명제를 만든다. 단순한 보완 관점, 정도 차이, 주제 전환은 반대 명제로 인정하지 않는다.

### 5.2 검증과 한 번의 자동 교정

별도 검증 단계가 다음을 판정한다.

- `direct_opposition`: 실제로 정면 반대인가
- `internal_consistency`: 반대 주장 내부에 모순이 없는가
- `source_traceability`: 무엇을 뒤집는지 원 착즙에서 찾을 수 있는가
- `grounding_integrity`: 제시한 인물·작품·텍스트가 근거 역할을 하는가
- `non_strawman`: 원 주장을 과장하거나 왜곡한 허수아비 반론이 아닌가

검증 실패 시 지적 사항을 포함해 한 번만 자동 교정한다. 두 번째도 실패하면 그럴듯한 결과를 강제로 노출하지 않고 `반대 관점을 충분히 검증하지 못했습니다` 상태를 세션에 남긴다. Distill 본문 자체는 보존한다.

### 5.3 외부 근거 검증

- 논문·책·텍스트는 가능한 경우 기존 OpenAlex 검증 경로를 재사용한다.
- 검증되지 않은 고유명사는 확정적 추천으로 표시하지 않는다.
- 실존 확인이 어려운 경우 구체 이름을 억지로 채우지 않고 방법론적 반대 방향만 제시한다.

## 6. 데이터와 API

### 저장소

- `POST /api/reservoir/:sourceId/deep-analysis`
  - body: `{ "profile": "precision" | "maximum" }`
  - raw 모델명은 받지 않는다.
- `GET /api/reservoir/:sourceId`
  - 최신 basic 분석과 최신 deep 분석을 구분해 반환
  - 심층 정리 이력 메타 포함

### 착즙

- `POST /api/distill/run`
  - body에 `includeCounter: boolean` 추가
- `distill_sessions.counter_enabled INTEGER NOT NULL DEFAULT 1`
- `counter_output_json`에는 결과와 검증 상태를 함께 저장
- 기존 세션은 마이그레이션 후 `counter_enabled = 1`로 간주

## 7. 실패·비용·접근성

- 월 AI 사용량 100%이면 심층 정리와 착즙 모두 실행을 막고 이유를 표시한다.
- 심층 정리 실패는 기존 기본 분석이나 자료 상태를 변경하지 않는다.
- Counter를 끈 경우 비용 원장에 Counter 호출이 생기지 않아야 한다.
- 모든 토글과 드롭다운은 키보드 조작과 명시적 레이블을 지원한다.
- 실행 버튼의 로딩, 성공, 실패 상태를 `aria-live`와 토스트로 전달한다.

## 8. 비목표

- 모델명을 UI에서 직접 편집하는 기능
- 사용자 임의 프롬프트 입력
- 심층 정리 결과의 자동 검색 인덱싱
- 무제한 전체 PDF 처리
- 외부 벡터 DB나 새 SaaS 도입
- Counter 결과를 사실이나 원문처럼 표시하는 것

## 9. 완료 조건

- 품질 프리셋 선택 후 기존보다 긴 본문으로 심층 정리가 생성된다.
- basic과 deep 분석이 서로 덮어쓰지 않고 각각 조회된다.
- 실제 모델명은 코드와 요청 body에 하드코딩되지 않는다.
- 반대 관점 토글은 기본 켜짐이며 세션별 값이 보존된다.
- 토글을 끄면 Counter 호출과 결과가 모두 생략된다.
- 토글을 켜면 검증을 통과한 정면 반대 명제가 결과 문서에 표시된다.
- 검증 실패는 명시적으로 보이고 기존 착즙 결과는 잃지 않는다.

## 10. 기존 스펙 변경점

기존 문서는 Counter를 모든 착즙에 무조건 자동 실행하도록 정의한다. 이번 사용자 결정으로 이를 `기본 켜짐이며 실행 전에 끌 수 있음`으로 변경한다. 구현 시 `docs/SPEC.md`, `docs/DEV_PLAN.md`, `docs/PROJECT_CONTEXT.md`, `docs/V1_GUIDE.md`의 관련 문구를 함께 갱신해 새 결정이 Source of Truth에 남도록 한다.
