# 받은 자료 우측 상세 패널 설계

## 목표

자료를 선택했을 때 페이지를 아래로 이동하지 않고, 목록 오른쪽의 고정된 읽기 패널에서 즉시 검수한다.

## 화면 구조

- 데스크톱(960px 초과): `자료 입력 | 최근 들어온 자료 | 선택 자료 검수`의 3열 그리드다.
- 입력 열은 280–340px, 목록 열은 280–360px, 상세 열은 남은 공간을 사용한다.
- 상세 열은 화면 상단에서 고정(sticky)하며 자체 스크롤로 긴 정규화문과 버전 이력을 읽는다.
- 선택 전에는 상세 열에 "자료를 선택하세요" 안내를 보인다. 요청 중에는 같은 위치에 "자료를 여는 중입니다"를 표시한다.
- 960px 이하에서는 2열(입력/목록) 아래에 상세를 배치하고, 760px 이하에서는 단일 열로 전환한다.

## 상호작용

- 목록 클릭은 선택 강조와 로딩 상태를 즉시 갱신한다.
- 최신 클릭의 응답만 상세 패널에 반영한다.
- 상세를 불러오지 못하면 기존 상세를 유지하지 않고 오류 상태를 패널에 표시한다.
- 클릭 시 페이지 전체 스크롤을 변경하지 않는다.

## 범위

- `InboxView`의 배치와 상세 요청 상태만 변경한다.
- 검수 데이터 API, 원문 보존, 분석 및 버전 액션은 변경하지 않는다.

## 검증

- 목록 클릭 직후 우측 패널의 로딩 상태를 확인한다.
- 늦게 도착한 이전 요청이 최신 선택을 덮어쓰지 않는지 테스트한다.
- 데스크톱에서 상세 패널이 목록 오른쪽에 렌더링되는지 CSS 구조로 확인한다.
