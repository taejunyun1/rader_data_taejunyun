# AI 모델 역할 선택 설계

## 목표

레이더·저장소·착즙의 전체 소화 과정에서 사용자가 자료마다 모델을 지정하지 않고, 설정 탭에서 두 역할의 모델만 선택하도록 한다.

## 확정 구조

- `기본 모델`: 일반 읽기, 청크 추출, 초벌 통합, 일반 반론 생성에 사용한다.
- `상위 통합·반론 검증 모델`: 중요 자료의 최종 통합, 반론 정합성 검증, 실패한 반론 재검토에 사용한다.
- 기존 `high`·`deep` 호출 계층은 유지하고, 실제 모델 ID만 설정값으로 덮어쓴다.
- 설정값은 기존 D1 `kv` 저장소에 보관한다. 저장값이 없거나 사용할 수 없으면 `MODEL_HIGH`·`MODEL_DEEP` 환경변수를 사용한다.
- 모델 목록은 서버가 OpenAI 모델 목록 API에서 가져온다. 브라우저에 API 키를 노출하지 않는다.
- 텍스트 생성에 적합한 GPT·o 계열만 목록에 표시하고 음성·이미지·임베딩·실시간·조정 모델은 제외한다.
- 저장 전 모델별 연결 시험을 실행한다. 시험은 최소 출력의 JSON 요청이며 `ai_usage`에 `model_validation`으로 기록한다.
- 가격 정보가 등록되지 않은 모델은 선택할 수 있지만, 보수적 상한 단가로 비용을 계산하고 설정 화면에 가격 미등록 경고를 표시한다.
- 실제 사용 기록에는 선택된 모델 ID를 남겨 기존 사용량 화면에서 확인할 수 있게 한다.

## 사용자 흐름

1. 설정 → AI 모델 역할로 이동한다.
2. 기본 모델과 상위 통합·반론 검증 모델을 각각 드롭다운에서 선택한다.
3. 새 모델 목록을 불러오면 현재 API에서 접근 가능한 모델과 등록 상태를 표시한다.
4. 모델을 바꾼 뒤 `연결 확인`을 누르면 최소 요청으로 호환성을 검사한다.
5. 두 모델의 연결 확인이 끝나면 `모델 설정 저장`을 누른다.
6. 이후 레이더·저장소·착즙은 자료별 선택 없이 저장된 역할 규칙을 사용한다.

## 서버 경계

- `GET /api/settings/models`: 사용 가능한 모델 목록과 현재 역할 설정을 반환한다.
- `POST /api/settings/models/test`: 선택한 모델 ID를 실제 호출해 Chat Completions·JSON 응답 호환성을 확인한다.
- `PUT /api/settings/models`: 두 역할의 모델 ID를 검증하고 `kv`에 저장한다.
- `callOpenAi`는 기존 tier를 입력으로 받고, `kv` 역할 설정 → 환경변수 순서로 모델 ID를 결정한다.
- 설정 조회 실패는 요청 전체를 중단하지 않고 환경변수 기본값으로 복귀한다.
- 모델 목록 조회 실패는 기존 설정을 유지하고 UI에 새로고침 가능한 오류를 표시한다.

## 비용·안전

- 모델별 알려진 가격은 환경변수 JSON으로 관리한다. 코드에 모델 ID를 가격표로 고정하지 않는다.
- 가격을 모르는 모델은 보수적 단가를 사용해 월 $10 guardrail이 실제 비용보다 낮게 계산되지 않도록 한다.
- 모델 설정 변경은 이후 호출부터 적용하며, 이미 저장된 분석 결과와 provenance는 변경하지 않는다.
- 모델을 삭제하거나 비활성화해도 기존 분석 기록의 모델명은 보존한다.

## 범위 밖

- 자료 카드별 모델 선택
- 모델별 프롬프트 편집
- 자동으로 최신 모델로 교체하는 기능
- OpenAI 외 공급자 모델 목록 통합
- 기존 분석 결과 전체 재생성
