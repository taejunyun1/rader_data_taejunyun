# 읽기 판단 바텀시트 디자인 사양

- 작성일: 2026-08-21
- 상태: 시각 방향 승인, 상세 사양 검토 대기
- 적용 화면: 발견, 저장소
- 선택 목업: `집중형 판단 시트` 1안
- 기준 문서: `docs/SPEC.md`, `docs/PROJECT_CONTEXT.md`, `docs/superpowers/specs/2026-08-21-research-radar-ui-design.md`

## 1. 문제와 목표

현재 `SplitWorkspace`는 1280px 미만에서 판단 레일을 전체 폭의 마지막 행으로 이동시킨다. 이 때문에 콘텐츠를 선택한 뒤 사용자가 긴 목록과 본문을 지나 페이지 하단까지 내려가야 분류할 수 있다.

발견·저장소에서 콘텐츠를 클릭하면 판단 UI가 현재 스크롤 위치와 무관하게 viewport 하단에서 즉시 올라오도록 바꾼다. 읽기 맥락은 뒤에 유지하고, 판단을 끝내면 원래 목록 흐름으로 빠르게 복귀하는 것이 목표다.

## 2. 확정된 경험

```text
콘텐츠 행 클릭
→ 해당 콘텐츠 선택 및 읽기 본문 갱신
→ 바텀시트 자동 열림
→ 발전/보관/관찰/제외 중 하나 선택
→ 처리 중 상태
→ 성공 시 시트 닫힘 + 목록 상태 갱신 + 짧은 토스트
```

- 발견과 저장소가 같은 바텀시트 컴포넌트를 사용한다.
- 콘텐츠를 새로 클릭하면 열려 있는 시트의 대상과 내용이 즉시 교체된다.
- 원문 링크 클릭은 외부 읽기 행동이므로 바텀시트를 열지 않는다.
- 분류 실패 시 시트를 닫지 않고 해당 행동 가까이에 오류와 재시도 상태를 표시한다.
- 원자료 보존 정책과 분류 변경 가능성을 시트 안에서 한 문장으로 안내한다.

## 3. 시각 구조

선택한 1안의 구조를 구현 기준으로 삼는다.

```text
┌──────────────────────────────────────────────────────────────┐
│                         drag handle                       ×  │
│  선택 자료 제목                                               │
│  후보/자료 유형 · 출처 · 연도 · 관련도                         │
│                                                              │
│  읽은 뒤 판단                                                 │
│  분류는 언제든 바꿀 수 있으며 원자료는 삭제되지 않습니다.       │
│                                                              │
│  ┌──────────────────────┐ ┌──────────────────────┐           │
│  │ 발전시키기            │ │ 보관하기              │           │
│  │ 연구 방향에 반영      │ │ 다시 읽기             │           │
│  └──────────────────────┘ └──────────────────────┘           │
│  ┌──────────────────────┐ ┌──────────────────────┐           │
│  │ 관찰하기              │ │ 제외하기              │           │
│  │ 흐름을 지켜보기       │ │ 추천 우선순위 낮추기   │           │
│  └──────────────────────┘ └──────────────────────┘           │
└──────────────────────────────────────────────────────────────┘
```

### 크기와 배치

- 시트는 viewport에 `position: fixed`로 고정한다.
- 데스크톱에서는 사이드바를 제외한 콘텐츠 영역 안에서 가운데 정렬한다.
- 기본 높이는 콘텐츠 기반 약 400~440px, 최대 높이는 `min(72vh, 560px)`로 제한한다.
- 900px 이하에서는 화면 전체 폭을 사용하고 모서리는 상단에만 적용한다.
- 시트 내부에만 세로 스크롤을 허용한다. 배경 문서는 열린 동안 스크롤을 잠근다.
- 배경 scrim은 검정 18~24%로 사용해 읽기 맥락은 남기되 현재 행동을 분명히 한다.

### 표현

- 표면은 흰색, 구획선은 기존 `--color-line`, 텍스트는 `--color-ink`를 재사용한다.
- 그림자는 시트 경계를 식별할 정도로만 한 번 사용한다.
- `발전시키기`만 보라색 주 CTA다. 그라데이션은 사용하지 않는다.
- 보관·관찰은 흰색 중립 버튼, 제외는 동일한 중립 버튼으로 두되 hover/focus에서만 위험 의미를 보조한다.
- 버튼은 아이콘보다 한글 행동명과 결과 설명을 우선한다.
- 선택 자료 제목은 최대 2줄 말줄임으로 처리한다.

## 4. 상태와 상호작용

### 열기와 닫기

- 후보/자료 행의 본문 영역 클릭 또는 Enter/Space 선택 시 자동으로 연다.
- 닫기 버튼, Escape, scrim 클릭, 아래 방향 드래그로 닫을 수 있다.
- 닫힌 뒤 focus는 직전에 선택한 콘텐츠 행으로 복귀한다.
- 화면 크기와 관계없이 동일한 바텀시트를 사용하며 기존 우측/하단 판단 레일은 제거한다.

### 액션

- 액션 버튼을 누르면 추가 확인 없이 기존 분류 API를 호출한다.
- 요청 중에는 네 액션을 모두 비활성화하고 선택한 버튼에 진행 상태를 표시한다.
- 성공하면 시트를 닫고 목록에서 처리된 항목을 제거하거나 상태를 갱신한다.
- 저장소의 `다시 분석하기`는 네 분류 액션 아래 구획선으로 분리한 보조 행동으로 유지한다.
- 저장소의 자료 기록 영역은 시트 하단의 접을 수 있는 보조 영역으로 이동하며 기본은 닫힌 상태다.

### 접근성

- `role="dialog"`, `aria-modal="true"`, 제목과 설명 연결을 제공한다.
- 열린 동안 focus trap을 적용하고 첫 focus는 닫기 버튼이 아니라 `발전시키기`에 둔다.
- 모든 액션은 키보드로 실행 가능하며 focus ring을 유지한다.
- `prefers-reduced-motion`에서는 이동 애니메이션 대신 즉시 표시한다.
- 일반 전환은 180~220ms ease-out으로 제한한다.

## 5. 반응형 기준

| 화면 폭 | 시트 구조 | 액션 배치 |
|---|---|---|
| 1280px 이상 | 콘텐츠 영역 중앙, 최대 960px | 2열 × 2행 |
| 900~1279px | 좌우 24px 여백 | 2열 × 2행 |
| 899px 이하 | 전체 폭, 상단 모서리만 | 1열 × 4행 |
| 낮은 viewport | 최대 72vh, 내부 스크롤 | 액션은 고정하지 않음 |

## 6. 컴포넌트 설계

### 새 컴포넌트

- `DecisionBottomSheet.tsx`
  - `open`, `document`, `context`, `pendingAction`, `error`
  - `onAction`, `onClose`, 선택적 `secondaryAction`, `children`
  - portal, focus trap, Escape, scroll lock을 소유한다.

### 기존 컴포넌트

- `DecisionRail.tsx`
  - 액션 정의와 표시 데이터는 재사용 가능한 `DecisionActions`로 분리한다.
  - 기존 inline `<aside>` 렌더링은 제거한다.
- `SplitWorkspace.tsx`
  - `decision` 열 prop을 제거하고 index + reading의 2열 구조로 단순화한다.
- `DiscoverView.tsx`, `ReservoirView.tsx`
  - 선택된 문서가 생기면 `DecisionBottomSheet`를 연다.
  - 분류 성공/실패와 선택 대상 교체 상태를 관리한다.
- `reading.css`
  - 기존 decision grid-column 규칙을 제거하고 sheet/scrim/motion/반응형 스타일을 추가한다.

API, Worker, D1/R2 스키마는 변경하지 않는다.

## 7. 구현 순서

1. 바텀시트 열기·닫기·포커스·Escape 동작의 실패 테스트를 작성한다.
2. `DecisionActions`를 기존 레일에서 분리해 행동명과 API 매핑을 보존한다.
3. portal 기반 `DecisionBottomSheet`와 scroll lock을 구현한다.
4. `SplitWorkspace`를 2열로 단순화한다.
5. 발견 화면에 자동 열기와 성공/오류 흐름을 연결한다.
6. 저장소 화면에 동일 흐름, 재분석, 자료 기록을 연결한다.
7. 1440px, 1024px, 768px 폭에서 시각 회귀와 키보드 흐름을 검증한다.
8. 타입 검사, 단위 테스트, 빌드, 핵심 E2E를 통과시킨다.

## 8. 완료 기준

- 발견·저장소에서 콘텐츠 클릭 후 스크롤 없이 판단 UI가 보인다.
- 네 분류 행동의 기존 API 의미와 결과가 바뀌지 않는다.
- 분류 성공 후 목록과 선택 상태가 올바르게 갱신된다.
- 오류가 발생해도 현재 읽기 맥락과 선택이 보존된다.
- 키보드만으로 열기, 액션, 닫기, 원래 위치 복귀가 가능하다.
- 899px 이하에서도 액션이 잘리거나 배경 문서가 함께 스크롤되지 않는다.
- 기존 한글화, 원문 링크, provenance 표현이 유지된다.

## 9. 비범위
